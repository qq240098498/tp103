# tp103 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

每个规则集归一个人或一组人管。页面右上角先选当前是谁在看，规则区只放开属于他名下规则集的规则可以改，别人管的规则照常列出但标成只读；规则不属于任何规则集时谁都不能改。范围可以叠加与切换：同一个人同时管两个规则集时两边都能改，切到另一个人时可见与可改的部分立刻跟着变。越权改动在提交当场就会被前后端一起拦下，并写清这条规则归谁管，不会先改再报错。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5103>

端口固定为 `5103`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 右上角先选当前是谁在看（选择会记住在本机）。规则表上方会写明当前列出多少条、其中可改几条、只读几条；可改的行正常显示编辑与删除，只读的行会置灰并写明「只读」，点不到编辑入口
2. 规则区列出编码、名称、级别、状态、适用文件类型、匹配写法、归属规则集与负责人，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；新建时要把规则归到自己名下的某个规则集，编辑时归属固定为原来的规则集不能挪动
3. 切到另一个人时，可改与只读的行以及顶部条数立刻跟着变；同一个人同时在多个规则集的负责人名单里时，这些规则集里的规则两边都能改
4. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单（文件区不按人分权限）
5. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；越权提交在发请求之前就会被页面拦下

## 归属口径

- 每个规则集有一个负责人名单（一个人或一组人），规则通过 `ruleSetId` 归到恰好一个规则集
- 当前操作者在某规则集负责人名单里，才能新建进该集、编辑或删除该集里的规则；同一人出现在多个名单里时范围取并集，自动叠加
- 一条规则不属于任何规则集（数据里 `ruleSetId` 为空，或指向已不存在的规则集）时，任何人都只能看不能改
- 规则的归属不能通过编辑修改，防止借编辑把别人管的规则换到自己名下
- 只读只约束写操作：清单、搜索、筛选、看内容与扫描对所有人一视同仁
- 前端的禁用与拦截只是第一道；每个写请求都带 `X-Operator` 头（百分号编码的操作者姓名），服务端在落盘前再判一次，身份缺失返回 401、越权返回 403 并写明规则归属与负责人

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "ruleSets": [...], "rules": [...], "files": [...] }`。规则集形如 `{ id, name, owners: ["林晓", "赵启"], createdAt, updatedAt }`，每条规则带 `ruleSetId` 指向它归属的规则集，空字符串表示不归属任何规则集。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。旧数据没有 `ruleSets` 时也会整体回落到带归属的初始数据，避免全部规则瞬间变成无归属。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rule-sets    | 规则集清单（含负责人、规则条数）与人员名单（含每人管的规则集） |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索；带 `X-Operator` 时每条规则返回 `editable` 与可改/只读计数 |
| POST   | /api/rules        | 新建规则（必须归到操作者名下的规则集，否则 403）  |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则（只有该规则所属集的负责人可以改；不能改归属） |
| DELETE | /api/rules/:id    | 删除规则（只有该规则所属集的负责人可以删）        |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总           |

规则的写操作（POST/PATCH/DELETE）都要带 `X-Operator` 请求头，值为当前操作者姓名的百分号编码（例如 `%E6%9E%97%E6%99%93` 表示「林晓」），不用百分号编码直接发 UTF-8 也能识别。缺头或为空返回 401 `OPERATOR_REQUIRED`；规则无归属返回 403 `RULE_UNOWNED_READONLY`；改到别人负责的规则集返回 403 `RULE_FORBIDDEN`/`RULE_SET_FORBIDDEN`，消息里写明规则集名称与负责人名单。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
